# AI Project Idea Generator (IdeaForge)

IdeaForge helps first-year B.Tech students discover practical project ideas, review the problem and suggested scope, and save a personal shortlist. It uses a curated local idea engine, so the core idea-generation workflow does not need a paid AI service or external AI API.

> **Admin account safety:** the requested admin email is `mrec@gmail.com`. Set a strong, private `ADMIN_PASSWORD` in `backend/.env` before running the server. Do not publish the password or commit `.env`. For safety, the distributed local template uses a placeholder rather than a reusable default password.

## 1. Problem and objectives

Students often struggle to turn broad interests into projects that fit their current skills and semester timeline. IdeaForge offers domain-based ideas, beginner/intermediate/advanced scope, suggested features and technologies, a demonstration tip, and a saved shortlist.

### Users and roles
- **Student:** create an account, sign in, generate ideas, inspect project details, save ideas, and remove saved ideas.
- **Administrator:** sign in with the configured admin account and view aggregate user and saved-idea counts. The admin does not see user passwords or individual private shortlists.

## 2. Features

- Responsive landing page and idea-generation form.
- Eight domains and three skill levels.
- Local curated idea templates; no external AI API is required.
- Idea details include problem, solution, features, stack, timeline, next steps, and demo tip.
- Sign up/sign in with bcrypt password hashing and signed, expiring JWTs.
- Personal shortlist stored persistently in Supabase PostgreSQL.
- Server-enforced student/admin permissions, request validation, rate limiting, Helmet security headers, and generic public server errors.
- Admin summary statistics and `/api/health` health check.

## 3. Technology and architecture

- Frontend: HTML5, CSS3, Vanilla JavaScript.
- Backend: Node.js and Express.js.
- Database: Supabase PostgreSQL.
- Supporting npm packages: `@supabase/supabase-js` (database access), `bcryptjs` (password hashing), `jsonwebtoken` (signed sessions), `dotenv` (environment configuration), `helmet` (security headers), `express-rate-limit` (request limits), and `cors` (restrictive cross-origin configuration).

The browser calls same-origin `/api/...` endpoints with `fetch()`. Express validates input, verifies the JWT and role, and accesses Supabase from the server. The Supabase service-role key is privileged and must never be sent to the browser. PostgreSQL RLS blocks direct `anon`/`authenticated` API access; the server performs authorization checks before using its privileged connection.

## 6. Supabase setup

1. Sign in to Supabase and create a new project. Keep its database password private.
2. Wait for the database to finish provisioning.
3. Open **SQL Editor**, choose **New query**, open `database/schema.sql`, paste the entire SQL, and click **Run**.
4. Open **Table Editor** and confirm `app_users` and `saved_ideas` exist.
5. In **Project Settings → API** (the exact menu label may vary), copy the project URL and the **service_role** key. The service-role key bypasses RLS, so it belongs only in `backend/.env`, never in browser code or GitHub.

The SQL enables RLS and denies direct access to public/ordinary API roles. Requests go through the Express server, which checks ownership and role. Never expose the privileged key to a frontend.

## 7. Configure environment variables

Open `backend/.env` and replace the placeholders:

```dotenv
PORT=3000
NODE_ENV=development
SUPABASE_URL=https://YOUR-PROJECT-REF.supabase.co
SUPABASE_SERVICE_ROLE_KEY=YOUR_REAL_SERVICE_ROLE_KEY
JWT_SECRET=REPLACE_WITH_A_LONG_RANDOM_SECRET
ADMIN_EMAIL=mrec@gmail.com
ADMIN_PASSWORD=REPLACE_WITH_A_UNIQUE_PASSWORD_OF_AT_LEAST_12_CHARACTERS
```

Generate a JWT secret from the **backend** directory:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Copy the output into `JWT_SECRET`. Change the admin password to a strong unique password and keep it private. When the server starts and the database is configured, it creates the admin account if absent. If that email already belongs to a non-admin account, bootstrap promotes it and updates its password to the configured admin password; therefore use the admin email only for the admin account. The bootstrap does not run when the password remains the placeholder or is shorter than 12 characters.

`.env` contains local secrets and is ignored by Git. `.env.example` documents variable names with safe placeholders and should be committed.

## 8. Install and run (Windows)

1. Extract or create the `ai-project-idea-generator` folder.
2. Open that folder in VS Code (**File → Open Folder**).
3. Open **Terminal → New Terminal**. Ensure the terminal is in the project root.
4. Install backend dependencies:

   ```powershell
   cd backend
   npm install
   ```

   This installs the packages listed in `package.json` and generates `package-lock.json`.
5. Configure `backend/.env` as described above and run the SQL in Supabase.
6. Check syntax:

   ```powershell
   npm run check
   ```

7. Start the server:

   ```powershell
   npm start
   ```

8. Open **http://localhost:3000** in your browser. Keep the terminal open while using the app. To stop the server, press `Ctrl+C` in the terminal.

For development with Node's file watcher, run `npm run dev` from `backend/`.

## 9. Main user workflow

1. Open Discover and select a domain, skill level, optional interest, and idea count.
2. Click **Generate ideas**. The template engine returns curated ideas without an external API.
3. Select **View details** to read the problem, proposed solution, features, stack, timeline, next steps, and demo tip.
4. Create an account or sign in, then select **Shortlist** on ideas you want to keep.
5. Open **My shortlist** to review and remove saved ideas. The data remains in Supabase after server restarts.
6. The configured administrator can open **Admin** to view aggregate counts.
7. Visit `http://localhost:3000/api/health` to check whether the server is running and whether the Supabase environment is configured. This endpoint does not prove the remote database is reachable; test sign-up/sign-in to verify database access.

## 10. REST API reference

All request and response bodies use JSON. Private routes require `Authorization: Bearer <token>` returned by sign-in/sign-up.

| Method | Path | Purpose | Auth / body |
|---|---|---|---|
| GET | `/api/health` | Server health and configuration flag | Public |
| POST | `/api/auth/signup` | Create student account | Public; `{ "name", "email", "password" }` |
| POST | `/api/auth/signin` | Sign in | Public; `{ "email", "password" }` |
| GET | `/api/auth/me` | Get current account profile | Signed-in user |
| GET | `/api/ideas/domains` | List domains and skill levels | Signed-in user |
| POST | `/api/ideas/generate` | Generate curated ideas | Signed-in user; `{ "domain", "skillLevel", "interests", "count" }` |
| GET | `/api/ideas/saved` | List current user's shortlist | Signed-in user; own records only |
| POST | `/api/ideas/saved` | Save an idea | Signed-in user; `{ "title", "domain", "skillLevel", "ideaData" }` |
| DELETE | `/api/ideas/saved/:id` | Remove an owned saved idea | Signed-in owner only |
| GET | `/api/ideas/admin/stats` | Aggregate user and saved-idea counts | Admin only |

Typical errors: `400` invalid input, `401` missing/invalid/expired token or incorrect login, `403` insufficient role, `404` resource/route not found, `409` duplicate account or saved idea, `429` rate limit exceeded, `503` database configuration missing, and `500` unexpected server error. Server logs contain diagnostic error messages; public responses do not expose raw database errors.

## 11. Database design

- `app_users`: account profile, unique email, bcrypt password hash, and role (`student` or `admin`).
- `saved_ideas`: user-owned saved ideas with domain, skill level, JSONB details, timestamp, foreign key with cascading delete, and uniqueness on `(user_id, title)`.
- Indexes support user's recent shortlist and domain filtering. An update trigger maintains `app_users.updated_at`.

The backend enforces ownership in SQL filters and role checks in middleware. The browser never supplies a trusted role or user ID.

## 12. Testing checklist

Run `npm run check` from `backend/` for JavaScript syntax checks. Then verify manually:

| Test | Action | Expected result |
|---|---|---|
| Health | Open `/api/health` | JSON status is `ok`; `databaseConfigured` is true after configuration |
| Sign up | Register with a valid new email and 8+ character password | Account created and user is signed in |
| Validation | Try invalid email, short password, or short name | Clear validation error; no account created |
| Duplicate account | Register the same email again | HTTP 409 duplicate-account message |
| Sign in | Enter correct credentials | Signed-in greeting and session token in memory |
| Wrong password | Enter incorrect credentials | Generic 401 message; no token issued |
| Generate ideas | Select a domain and click Generate | Idea cards and detail dialog appear |
| Invalid generation | Send an unknown domain or count above 8 via API | HTTP 400 validation response |
| Save idea | Sign in and shortlist an idea | Idea appears in My shortlist and remains after refresh/sign-in |
| Duplicate save | Save same title again | HTTP 409; duplicate not stored |
| Ownership | Attempt to delete another user's saved-idea ID | No other user's record is deleted; normally 404 |
| Sign out | Click Sign out, then try private API without token | UI signs out; API returns 401 |
| Admin | Sign in as configured admin and open Admin | Aggregate counts display |
| Role control | Call `/api/ideas/admin/stats` as student | HTTP 403 |
| Database outage | Temporarily use an invalid Supabase URL/key | Requests show a friendly failure; server terminal has diagnostics |
| Responsive UI | Test at desktop and narrow mobile widths | Layout fits screen and controls remain usable |
| XSS safety | Save text containing HTML-like characters as an interest | Text is escaped in rendered content and does not execute as HTML |

These are test instructions, not a claim that a real Supabase instance has been connected or tested. Automated tests against a live database are not bundled because they require your own project credentials.

## 13. Troubleshooting

- **`npm` or `node` not recognized:** install Node.js LTS, close and reopen the terminal, then rerun version commands.
- **`Cannot find module`:** from `backend/`, run `npm install`.
- **Database configuration error:** confirm `backend/.env` exists, has no quote/space mistakes, and contains the correct project URL and service-role key. Restart the server after edits.
- **Supabase relation/table error:** run the complete `database/schema.sql` in the correct Supabase project's SQL Editor.
- **Admin cannot sign in:** set `ADMIN_EMAIL=mrec@gmail.com`, choose a password of at least 12 characters, confirm Supabase credentials, restart the server, and read the terminal bootstrap message.
- **Port already in use:** set another unused `PORT` in `.env`, then restart and open the matching local URL.
- **Expired session:** sign in again. JWTs expire after eight hours and are held in browser memory, so refreshing the page also requires signing in again.
- **429 rate-limit response:** wait for the configured rate-limit window to reset.
- **Do not paste real secrets into issue trackers, screenshots, or public chat.** Rotate a key immediately if it becomes exposed.

## 14. Security and limitations

- Passwords are hashed with bcrypt; plaintext passwords are never stored.
- JWTs expire after eight hours. The frontend keeps the token in memory rather than `localStorage`; refreshing the page signs the user out.
- The service-role key bypasses RLS and is used only by Express. Protect the server and `.env`.
- Admin bootstrap uses `ADMIN_PASSWORD` to initialize/reset the configured admin password at startup. Treat that environment variable as a secret.
- Rate limiting and Helmet headers are enabled. This same-origin app does not use cookie sessions, so cookie-based CSRF defenses are not applicable; do not move authentication into cookies without adding suitable CSRF protection.
- The idea generator is a curated rule/template engine, not a generative AI model. This is intentional to keep the core project free of external AI services. Future work could add user ratings, exports, mentor feedback, more templates, or an optional AI provider behind a carefully secured server API.

## 15. Git and GitHub upload

1. Create a new empty repository on GitHub. Do not add a README there if your local root already has one.
2. Open a terminal at the project root and check `.gitignore` before adding files.
3. Run:

   ```bash

   git status
   git add .
   git status
   git commit -m "Build AI Project Idea Generator"
   git branch -M main
   git remote add origin YOUR_GITHUB_REPOSITORY_URL
   ```

4. Replace `YOUR_GITHUB_REPOSITORY_URL` with the URL of your own repository.
5. Verify the repository contains source code, `database/schema.sql`, `.env.example`, and `README.md`, but **not** `.env`, `node_modules/`, service-role keys, passwords, or database exports.
